# duo-content-weekly-workflow — 内容运营周循环

> 角色：Windows 侧内容运营。排期 = 唯一圣经，成品 = 多多审核，to_publish = 发布助手执行。
> 适用范围：短文（X/Threads/微博/即刻/知识星球/小红书）+ 长文（公众号/Medium/Substack）。
> 与 `duo-socialpublish-cdp`（发布执行）和 `duoduo-voice-deai`（语气重洗）配合使用。

---

## 〇、排期总纲（先读这段，决定一切 · 血泪定论，禁止漂移）

1. **唯一排期文件 = `05_CONTENT/发布排期.html`**（iCloudDrive 同步盘，内容运营 + 发布助手都能看到）。**不再移动、不再改名、不再另起第二份、不再生成其他排期副本。** 任何周次的更新都只改这一个文件（追加下周块 + 回填上周实际 + 滚动丢弃最旧周）。
2. **桌面两个入口都指向同一份单文件**（不要出现第二份）：
   - `E:\OneDrive - National University of Singapore\Desktop\多多OS发布排期.url` → 已指向它。
   - 同名 `.lnk` → 二进制快捷方式，改指向需用 Python 重生成（见 §二 末）。若已指向则跳过。
3. **内容完整铁律**：重构 / 合并 / 加主页 / 加下周时，必须**完整保留**所有逐日预览（scard 文案全文 + 配图 + 标签），用「插入」而非「重写覆盖」；新增模块（主页 / 分周频次核对 / 下周）不得丢弃旧内容。若用户另有旧版排期文件（如 deliverables 的 `发布排期_0731-0807_脚本审核v2.html`），以它为基底做加法，**不另起简化文件**（曾发生：另起简化版把 44 张逐日预览全丢了，被用户痛批「越做越差」）。
4. **禁止编造铁律 🔴**：任何 EP 编号 / 发布日期 / 标题 / 第几期，只在 `05_CONTENT/03 drafts/` 有真实依据时才填。drafts 无日期/无标题/不存在的条目 → 先按「无排期 / 无标题」排入，**红色标 `⚠ 待确认`**，汇总交多多确认。**绝不凭空编**（曾发生把播客和视频都编成 EP05–08 的事故）。
5. **频次核对双重 + 语义严格分工（最易错，见 §三）**：
   - 每周排期段**底部**表 → 只查「计划排期 vs SOP 要求频次」一致性（**无状态列、无实际发出列**）。
   - **单列「分周频次核对」**（历史周/本周/下周 三张）→ **唯一承载「状态 + 实际发出频次」的板块**。
   - 二者不可混。曾发生把状态+实际两列塞进段底表，被用户要求「恢复最早那版语义」。
6. **排期 = Mac 导演 / 内容运营 / 发布助手 三方唯一圣经**。
7. **周四流程顺序（详见 §一）**：先回填上周实际发出频次 → 再核对 drafts 真实排期 → 再在单文件内追加下周块（与本周同结构）→ 滚动丢弃最旧周 → 无依据项标 ⚠ 待确认。
8. **交付纪律**：排期改完 → `present_files` 交多多确认；**未确认前不写文案、不进 drafts、不发布**（除非用户明确指令）。

## 〇·五、脚本内容铁律（来源标注 + 直接取库内原声 · 最高优先级）

> 触发：往排期填任何短文/长文 scard 文案时。这条是「越做越差」重灾区和被痛批点（2026-08-07：脚本被改得面目全非 + 不注明来源）。

1. **每篇脚本必须标注来源成稿**：scard 内加一行 `来源：🧷XX 成稿NN《标题》` + 内容库 `.md` 文件链接（`E:/.../05_CONTENT/02 developing/🧷XX_...md`）。来源只能是 `02 developing` 里按方向存的成稿（🧷03 C1 / 🧷04 C2 / 🧷05 C3 / 🧷06 C4 / 🧷08 C5），不许编。
2. **直接取库内原声，禁止二次重洗改写**：成稿本身就是多多原声（已去 AI 味、已按平台分好版）。填文案时**逐字取用**，只允许两种改动：① 按平台字数上限**截取**（微博/即刻≤200、X≤280、小红书≤1000）；② **X / Threads 写英文翻译版**（库里无英文稿，翻译须忠实原意，不得另起炉灶改写）。其余平台（微博/即刻/知识星球/小红书）一律用库内原文，不得再过 `duoduo-voice-deai` / `EN 重洗` 把原声改写散。
3. **库里已有现成平台版就直接用**：C4/C5 成稿里已存「小红书版 / 即刻短版」，微博可用小红书版截取、即刻用即刻短版原样。不要凭空重写。
4. **配图用成稿指定的图**：每个成稿自带 `## 配图` 列表，scard 默认配图取该列表里的图（核对磁盘存在，缺失则换同列表其它张，绝不瞎配）。
5. **C2/C3（0812/0813 等 Mac 日）内容运营不写视频/图文预览**，但**仍须由内容运营把这些日的视频 slots 排进频次表**（如 0812 排 DUODUO WEAR/IG 视频、0813 排世斐）+ 在 script-note 标 `素材来源：🧷04 / 🧷05`，让来源可溯源。排期责任在内容运营，产出在 Mac。
6. **文件名锁死**：单文件只能叫 `发布排期.html`。iCloud 同步偶尔会生成 `发布排期 2.html` 之类副本——发现后立刻 `os.replace` 合并回 `发布排期.html` 并删副本，桌面 `.url`/`.lnk` 双入口才不断。
7. **用过即标注（内容库成稿溯源 · 2026-08-08 定）**：凡把 `02 developing` 里某篇成稿写进 scard（短文组），**必须同步在该成稿标题后加备注**。格式固定：
   `## 成稿N · 标题　✅ 已用于发布排期：MMDD（认知·短文组）`
   - 目的：追溯已用稿、防同一成稿被重复排或漏排。每月排期后 grep `已用于发布排期` 核对一遍，确认每篇被用成稿都已标。
   - 公众号/播客/视频等取自 `03 drafts/` 的 to_publish 长文不在 `02 developing` 成稿库，只按 §〇·五·1 在 scard 挂来源，不在库标题备注。
   - ⚠ 漏标的判定：排期 scard 里出现「来源：🧷XX 成稿NN」但该成稿标题后无「✅ 已用于发布排期」备注 = 漏标，必须补。
8. **排期责任分工（2026-08-08 纠正「搞反了」·铁律）**：① **公众号 + 播客 = 按导演（Mac）安排**——以 `03 drafts/` 里导演排好的为准反映排期，频次表标「⚪ 按导演安排（drafts✓）」，归属写「导演(drafts)」，内容运营不自行认领、不标「✓ 文案已写」。② **其余所有平台（含视频号/抖音/世斐/DUODUO WEAR 视频/IG 视频等 Mac 产出的）= 内容运营先定排期、标好日期**，Mac 再按排期产出。⚠️ 没有 draft 不等于空着、不等于只标红「需 Mac 产出」——内容运营照样把 slots 排进频次表（标「✓ 排期已定（计划N≥SOP）· 视频 Mac 按排期产出」）。检查 drafts 有稿是对的，但没稿也要先排期。

## 一、周四排期生成 SOP（逐步照做，不要再问）

> 目标：在 `05_CONTENT/发布排期.html` 这一个文件里，完成「回填上周实际 + 排下周 Mon–Sun + 滚动窗口」。每一步都基于现有文件做加法，不新建文件。

**Step 0 — 打开唯一单文件，读取现有结构**
- 读 `05_CONTENT/发布排期.html`。确认它含：主页概览 / 单列分周频次核对（历史周·本周·下周 三张）/ 历史周段 / 本周段 / 下周段。每周段 = 每日预览(scard 全文+配图+标签) + 段底「计划 vs SOP 一致性」表。
- 若文件不存在/结构不符，先向用户报告，不要擅自新建（钉死规则：只用这一个）。

**Step 1 — 回填「上周实际发出频次」**
- 数据来源（按优先级）：① `05_CONTENT/04 Published/` 下的 `published_日期_账号.md` 本地发布记录（短文账号的权威真值）；② 发布助手运行信息；③ 各平台主页核验。
- Mac 侧发的（播客 / 视频 / 公众号长文部分）本地无记录 → 该格标「**待各平台核验**」，不要瞎填。
- 把算出的「实际发出频次」写入**单列分周频次核对**里对应「上周」那张表的「实际发出频次」列（最后一列），并据实更新「状态」列（已发/待发/漏发）。
- ⚠ 纠偏价值：用真实记录打脸虚报。例：曾虚报「0803–0809 短文 5 天全✓」，实际 `04 Published/` 只有 0803–0804，07/08/09 未发 → 必须改回 ⚠。

**Step 2 — 核对 drafts 真实排期（公众号/播客唯一真值源）**
- 扫 `05_CONTENT/03 drafts/` 下 `to_publish_*.md` 与 `To publish_<主题>/` 文件夹，提取已标好的**公众号 / 播客**真实：第几期 + 标题 + 发布日期。**公众号与播客按导演（Mac）安排**，drafts 里排好的就是导演排期，内容运营据实填入、标「⚪ 按导演安排（drafts✓）」，不自行认领。
- ⚠️ **视频 / 世斐 / 短视频等 Mac 产出的平台不走这条**：它们由**内容运营先定排期**（在频次表排好日期/slots，如 Boost 日 0814/0815/0816 排视频号/抖音、0813+0816 排世斐），Mac 再按排期产出。内容运营**不写视频脚本，但要排日期**——没有 draft 也要先排期，频次表标「✓ 排期已定 · 视频 Mac 按排期产出」，严禁空着或只标红「需 Mac 产出」。
- 排期责任分工铁律见 §〇·五·8。

**Step 3 — 滚动窗口 + 追加下周块**
- 旧「本周」→ 变为「历史周」；旧「下周」→ 变为「本周」；新增「下周（新 Mon–Sun）」。
- 新下周段**必须与本周段同结构**：7 天每日预览（scard 框架，文案待写时标「待写」）+ 段底「计划 vs SOP 一致性」表（账号行与本周完全一致，12 行）。
- 新下周段：公众号/播客据 drafts 已排者填真实日（标「⚪ 按导演安排」）；**视频/世斐/短文组等由内容运营按 C 日轮转 + Boost 规则主动排期**（即使无 draft 也要排 slots，标「✓ 排期已定」），不得整体留 ⚠ 待确认。
- C 日轮转 & 周末 Boost 规则见 §七。
- **每篇短文组 scard 落定后，立刻回 `02 developing` 对应成稿标题后加备注**（格式见 §〇·五·7：`✅ 已用于发布排期：MMDD（认知·短文组）`）。这是硬步骤，不得排完就忘；交付前 grep 自检一遍漏标。

**Step 4 — 更新单列分周频次核对（三张表）**
- 历史周 / 本周(新) / 下周(新) 各一张，列 = `账号 | SOP 周频次 | 本周边排期 | 状态 | 实际发出频次`。
- 把 Step1 回填的「上周实际」落在对应的历史周表；本周/下周实际列标「—（待发）/ 待各平台核验」。
- SOP 周频次值从 §四 参考表抄（已确认），或直接从本文件现有 tally 的「SOP 周频次」列照抄（它们就是工作参考源）。

**Step 5 — 同步桌面入口**
- 若 `.url` 与 `.lnk` 已指向 `05_CONTENT/发布排期.html` → 跳过。
- 若需改 `.lnk` 指向：用 Python 二进制重生成（UTF-16LE 嵌入目标路径 + 设 IsUnicode flag），不要用普通文本编辑器改 `.lnk`。
- 删除/停用任何指向旧副本（如 deliverables 旧 v2）的入口，避免双文件漂移。

**Step 6 — 自检（发布前必须做）**
- grep 确认：① 无 `EP0[5-9]` 等编造编号（除非 drafts 真有）；② 两张段底表头 = `账号|SOP周频次要求|计划排期|与SOP一致性`（无状态/实际列）；③ 单列三张表头含 `状态|实际发出频次`；④ 每周段底部表账号行数一致。
- 无依据项全部 `⚠ 待确认`，无遗漏。

**Step 6.5 — 自动校验闸门 🔴（生成后必跑，2026-08-09 补·血泪教训）**

> ⚠️ 此步骤为强制性闸门——校验不通过不得进入 Step 7（交付多多）。2026-08-09 事故：排期生成完直接 present，5 篇 X 帖全超 280 字符、0814/0815 同天双发、0812 日表与 tally 日期矛盾——全是可自动检测的 bug，因缺此闸门全部漏到多多面前。

跑以下 Python 校验（可封装为函数，但必须跑完再交）：

1. **X 字符数**：grep 所有 `X · @faifaida1` 卡片的 `<div class="copy">` 正文，`len()` ≤ 280，超者标红列出。
2. **同天双发冲突**：扫描下周每日的 scard 账号，任一天同一平台（小红书·多多OS / IG 等）scard ≥ 2 → 标红。
3. **段底表 ↔ tally ↔ 日表一致性**：
   - 段底表「下周计划排期」数字 → 提取 → 与对应日实际 scard 计数比对。
   - tally ③ 各账号的「本周边排期」文字 → 与段底表同账号行比对。
   - 日表里标注的视频日期 → 与 tally 里的视频日期比对。
4. **tag 格式**：小红书 scard 的 # 标签 → 逐条核全为 `#xxx#` 双#（不得出现单#尾巴无#）。
5. **账号行一致性**：段底表账号行数 = tally ③ 账号行数。
6. **日表实体 ↔ 频次表双向比对 🔴（2026-08-09 事故根因）**：凡频次表 / 段底表 / 底部自检汇总里某账号行写「已排 / ✓ 排期已定 / 各N达标 / 0813+0816」等表达「已排期」的——**必须**在该账号对应的日期日表 `<table>` 里存在对应账号行（如世斐写「0813+0816」→ 0813 日表与 0816 日表都须有世斐行）；反之，日表里出现的每个视频 / 世斐 / Mac 视频 slot，频次表也必须有对应条目。任一方向缺失 → **标红 FAIL，禁止进 Step 7**。绝不允许频次表虚报「已排」而日表漏行。

校验跑完 → 输出 PASS/FAIL 报告 → PASS 才进 Step 7。

**Step 7 — 交付**
- `present_files` 指向 `05_CONTENT/发布排期.html` 交多多确认。
- 未写文案、未发布（除非用户当次明确指令）。

## 三、频次核对：双重 + 语义严格分工 🔴（最易错，务必区分）

| 位置 | 表头（列） | 查什么 | 不查什么 |
|---|---|---|---|
| **每周排期段底部**（本周/下周 各一张） | `账号 \| SOP 周频次要求 \| 本周/下周计划排期 \| 与 SOP 一致性` | 计划排的篇数 **是否达到 SOP 要求** | ❌ 状态 ❌ 实际发出 |
| **单列「分周频次核对」**（历史/本周/下周 三张） | `账号 \| SOP 周频次 \| 本周边排期 \| 状态(已发/待发) \| 实际发出频次` | 状态 + 实际发出频次（唯一承载这两项） | — |

- 段底表只标 `✓ 达标` / `⚠ 缺X篇`（计划数 < SOP 要求）。

### 平台标签格式铁律（2026-08 实测核实；平台规则会变，生成时以 composer 实际为准）

- **小红书 XHS**：`#话题#`（双#，开头结尾都有#）。缺结尾#在 XHS 不生成可点话题=白写。多标签：`#女性创业# #一人公司#`。
- **微博**：`#话题#`（双#，同 XHS 结构）。一条最多带 **3 个**话题。
- **即刻**：`#话题`（单#，可空格）。即刻主要靠圈子分发，标签可放 0-1 个。
- **知识星球**：`#话题 `（单# + 空格结尾，网页端输入#即建标签）。0-2 个。
- **X**：`#topic`（单#，英文 camelCase/无空格如 #BuildInPublic）。1-2 个，>2 像 spam 且吞字符。
- **Threads**：`#topic`（单#英文）。⚠️ **每帖仅 1 个 topic tag**，多放无效/被吞；常放 0 也合法。
- **Instagram**：`#topic`（单#英文）。⚠️ **2025-12 起上限 5 个**（旧 30 已作废），建议 3-5 个；超 5 在 composer 被拦。
- **公众号**：2025-05 起正文支持 `#关键词`（单#，自动变蓝色可点，搜一搜可检索）+ 底部最多 3 个分类标签（每标签≤10字）。
- **Medium / Substack**：发布时选**纯文字标签**（不带#）；Medium≤5、Substack 0-5。
- 🔴 **铁律**：小红书绝不写单 `#话题 `（那是微博/即刻/X 写法）。每张小红书卡生成后逐条核标签全为 `#xxx#` 双#；发布前再核一遍。

### 字数硬约束（每条 scard 必过）

- 每条 scard 正文必须 ≤ 该平台字数上限（见上表）；超限必须截断或换版本，不得"差不多"。
- 有标题平台标题必须达标：小红书≤20字 / 公众号独立标题 / Medium<100字 / Substack<60字 subject。
- 生成时每条 scard 标注核验行：`字数 N / 上限 M ✅` 或 `标签 K 个（平台范围 ✅）`，便于审核一眼核验。

### 无标题平台铁律（防首句两次）
- X/Threads/微博/即刻/知识星球/Instagram **没有标题栏**。

## 八、内容生产流程

### 1. 素材发掘
- 来源：`07_Journals/01 Daily/*.md`（日记）、`04_KNOWLEDGE WORK/`、`01_INBOX/`。
- 筛选原则：真实事件、已发生的、有情绪的、符合某个 C 方向的。
- 不虚构；未发生在多多身上的事不写。

### 2. 写作（短文 / 长文）
- 短文：100-300 字核心稿（一个内容一版本，不分平台），先写 CN 再翻 EN。
- 长文：公众号源取 `🧷07_长文发布内容库-多多os`，Medium/Substack 源取日记（外网不写接班）。
- 语气 = 多多原声（毛边、不鸡汤、碎片感、中英混排、不 hedge）。
- 零 em-dash（英文），"——" 分隔符保留（中文）。

### 3. 去 AI 味
- 必须走 `duoduo-voice-deai` 技能（中英文都走）。
- CN → `qu-ai-wei`；EN → `humanize-en`。
- 不改选题/事实，只重洗语气 + 排版。

### 4. 配图
- 首选 `02_CONTEXT/多多照片/`（斯里兰卡surf/太极课、油化厂、旅行照）。
- 次选 `05_CONTENT/00 photo_materials/`。
- 先找，找不到再问多多。

### 5. 排期回填（详见 §一 SOP）
- 写好的短文直接嵌入排期 HTML 对应的 `.day` 区块下方（scard 卡片，全文可见）。
- 长文可嵌全文或放 teal 预览按键（链接到独立预览文件）。
- 公众号全文 = 真海浪底版独立 HTML（排期内只放预览按键）。
- **频次核对规范见 §三**（双重 + 语义分工），不要在本节重复造表。

### 6. 审核
- 多多在排期 HTML 里看成品 → 用 `== ==` 高亮批复。
- **铁律：在多多确认前，任何 to_publish 文件都不进 `03 drafts/`**。
- 未确认内容暂存 `deliverables/_pending_to_publish/`。

### 7. 交接发布助手
- 多多 `== ==` 拍板后 → 生成 `to_publish_*.md`（status approved），放入 `05_CONTENT/03 drafts/`。
- 发布助手每日 10:00/22:00 自动扫描该目录执行 CDP 发布。
- 发布入口 = `E:\iCloudDrive\iCloud~md~obsidian\DuoDuo_AI_Workspace\05_CONTENT\03 drafts\`。
