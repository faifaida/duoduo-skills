# Weekly Life OS · 周历整合

多多个人生活操作系统（Life OS）的每周仪式：把「上周日记复盘」和「月相周期 + 个人生活系统」融汇成一份下周计划，并写入系统日历。核心哲学来自 `02_CONTEXT/08 多多生活系统.md`：**Follow Earth. Not Calendar.** ——不可移动现实责任 → 季节/浪季/地点 → 身体与项目 → 月相/节气象征节奏。

## 何时触发
- 用户说「周复盘 / 下周计划 / 周简报 / 月相周 / 把月相融进日历 / 和下周对齐」。
- 建议在每周一或周日启动；若用户日记已写到今天，直接基于「上周一→今天」的日记做。

## 输入文件（相对 Vault 根）
1. `07_Journals/01 Daily/<YYYY>/`（2026-08-03 起按年归档，读「上周一 → 今天前一日」日记时遍历对应年份子目录，如 `01 Daily/2026/`）—— 读日记，提炼复盘素材（最生命力/最耗能时刻、反复主题、未完成任务、身体情绪睡眠信号）。
2. `02_CONTEXT/08 多多生活系统.md` —— Life OS 权威文件：北极星(Alive)、年度四季、滚动月相四段、节气、复盘五问、Alive 仪表盘、系统保护规则。**每周必读并融汇。**
3. `03_ACTIVE PROJECTS/ai个人公司/公司总部/00_公司状态.md` + `02_活跃项目.md` —— 公司侧不可移动事项（如知识库上架、青旅节点），避免与个人日历冲突。
4. （可选参考）`01_INBOX/AI_CONTEXT_EXPORTS/Chatgpt context/月相周期和品牌_2026-07_v2/08 个人生活系统.md` 是 v0.3 更完整版，若 02_CONTEXT/08 过简可对照。

## 当前月相定位方法
- 月相四段（每段约 7–8 天，滚动、不从周一切；按多多 2026-07-22 批复统一）：
  - 🌑 新月→上弦 = **启动期** · 对外说法：支线任务 · 创意表达支线 / 个人提升 / 生活方式（创意表达 / 学习 / 开始实验 / 建立新结构）
  - 🌓 上弦→满月 = **推进期** · 对外说法：支线任务 · 身体 / 自我 / 美丽（身体能量 / 重复练习 / 解决阻力 / 深度建设）
  - 🌕 满月→下弦 = **爆发 · 释放期** · 对外说法：支线任务 · 生活项目 / 探索 / 关系（完成 / 发布 / 展示 / 活动 / 销售反馈）
  - 🌗 下弦→新月 = **收尾 · 内观期** · 对外说法：主线任务 · 青旅 / 事业主线 / 职业 / 资源 / 个人公司（整理 / 复盘 / 减少扩张 / 修复休息）
- 不代表月相客观导致能量，只是多多采用的行为提示；现实截止日期、合同、现金流优先。
- **如何拿当前月相**：查当月月相节点（新月/上弦/满月/下弦的具体日期，可用 WebSearch「YYYY MM moon phases」或天文算法），判断本周落在哪一段，据此建议「这周适合推进什么、不适合什么」。
- 参考锚点（2026）：新月 7/14、上弦 7/21、满月 7/29、**下弦 8/6**、下一次新月 8/13。🔑 周级定调（2026-08-03 多多）：含满月尾巴的那一周 = 🌕 爆发/释放（生活项目）；其下一周 = 🌗 收尾/内观（事业主线 / 决策清障）。

## 六维周计划输出格式（固定）
1. **最生命力 vs 最耗能时刻**（来自日记）
2. **下周不可移动的工作与生活安排**（硬日程）
3. **当前身体 / 情绪 / 睡眠状态**（从日记推断，标「需用户确认真实状态」）
4. **四方向推进**：青旅/工作主线、身体与能量、创意变现、大生活项目
5. **最重要一件事 + 最想避免的陷阱**
6. **节奏偏好 + 可做/不做清单 + 一个让生活有趣的行动 + 周末复盘问题**
   - 节奏偏好选项：冲刺 / 恢复 / 整合 / 探索
   - 周末复盘问题需包含 Life OS 月相五问：本阶段唯一主要结果完成了吗？什么让我更 Alive？什么在消耗我？四项中哪项被挤压？下阶段要停止什么？

> 不要把每一天排满——保留弹性和偶然性。

## 日历写入（iCloud CalDAV — 永久免权限方案，2026-07-22 切换）
- **机制**：走 **CalDAV 协议直连 iCloud 日历服务器**（`caldav.icloud.com`），**不依赖 macOS 自动化 / Apple Events 授权**，因此不需要在「系统设置→隐私与安全性→自动化」开任何开关，也不会会话失效。授权用「应用专用密码」（appleid.apple.com 生成、可随时吊销），存在本机 `~/.workbuddy/caldav_config.json`（权限 600）。
- **🔑 为什么弃用 osascript / caltool（关键，勿回退）**：`osascript` 控制 Calendar.app = Apple Events 自动化，把授权授予「每次会话身份都变」的助手进程 → 会话一换授权就丢、反复 `-10004`；自建 `caltool`（ad-hoc 签名）也无法在「自动化」列表注册稳定身份（用户实测列表里找不到它）。两条自动化路线在此机器都是死路。**一律改用 CalDAV。**
- **工具与运行**：`/Users/Zhuanz/.workbuddy/caldav/caldav_tool.py`（Python + requests，跑在 `~/.workbuddy/binaries/python/envs/default` venv）。内部已 `proxies={"http":None,"https":None}` 绕过沙箱代理直连；调用前 `unset HTTP_PROXY HTTPS_PROXY http_proxy https_proxy` 更稳。
- **命令**：
  - 列日历：`python caldav_tool.py list`
  - 列事件：`python caldav_tool.py events --calendar <名> [--from <YYYY-MM-DD> --to <YYYY-MM-DD>]`
  - 新增：`python caldav_tool.py add --calendar <名> --title <t> --start <YYYY-MM-DDTHH:MM> --end <...> [--notes <n>]`
  - 删（按标题匹配）：`python caldav_tool.py delete-match --calendar <名> --contains <文本> [--from <d> --to <d>]`
  - 删（按 href）：`python caldav_tool.py delete --href <href> [--etag <e>]`
- **多多的真实日历/颜色**（已探测，直接用，不新建）：个人（紫）、美美美（粉/美丽）、工作、运动、探索、社交、家人、活动、个人提升、玩手机、会议。
- **事件归属建议**：日常/journal/心理/针灸/车改造/遛狗→个人；纹身/编绳首饰/护肤/剪头发/洗牙/按摩→美美美；青旅/视频/知识库/发票/金子编绳→工作；网球/健身→运动；老君庙/家人→家人；dan koe 课→个人提升。
- **iCloud CalDAV 实测坑（2026-07-22 已踩并修）**：
  - `calendar-query` 的 REPORT **必须带 `Depth: 1`**，否则只返回日历集合本身（空）。
  - 过滤必须显式包 `<c:comp-filter name="VEVENT">`（无日期时此空包装匹配全部事件）。
  - `calendar-data` 用 `<![CDATA[...]]>` 包裹；解析取 `{urn:ietf:params:xml:ns:caldav}calendar-data` 的 `.text`。
  - 时间范围用 UTC `YYYYMMDDTHHMMSSZ`；本地时间事件会落在对应 UTC 区间，按日期过滤时包含全天 UTC 即可覆盖。
  - iCloud 返回**绝对 URL**（含 `pXXX-caldav.icloud.com` 主机），拼接请求时必须直连、不能再叠 `caldav.icloud.com` 前缀。
- **冲突处理（用户 2026-07-22 强调）**：新排事项与已有事项冲突时（如**全天外出 100km 与当天健身**、一件事被拆成两条占位），**先判断能判断的、判断不清就问用户，绝不硬放**。例：老君庙全天→当天不排健身、把健身房那次挪到相邻空闲日；晚饭+遛狗+备餐是同一件事，合并一条并在 notes 备注，不拆多条。
- **标灰**：用户明确「日历没有标灰」，故**不做标灰**，未完成任务仅在周计划文档里标 ❌。
