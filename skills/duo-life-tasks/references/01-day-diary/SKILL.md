# duoduo-day-dy · 当日日记汇总（严格对齐 IMA day dy 真版）

> **权威来源**：`references/daily-diary-skill-full.md`（多多 2026-08-03 从 IMA 导出的真版，已存档）。本 skill 是它的**对齐实现**，不是猜测。改这个 skill 前先读真版。
> 与早期重建版的根本区别：早期版错写成「结构化汇总 / 提炼要点」，**违反真版铁律**。真版铁律是**保留原文压倒一切**。
> 我们流程 vs 真版 IMA 的唯一差异：① 输入来自 notes 采集箱（prepare JSON），非 IMA qa 层；② 额外加 `## 🎙️ 当日录音` 段内嵌真实音频（IMA 无音频，vault 有）；③ `source: 苹果录音`（真版 ima）。

## ⚠️ 铁律：保留原文压倒一切

```
保留原文 ＞ 真实性 ＞ 可回忆性 ＞ 清晰度 ＞ 文学性
```

- **用户原话**：不加引号，直接写原句（出现在 Bullet Points 中）。
- **非用户的话**（AI 分类 / 小结 / 观察）：用 📌 标记，一眼可区分。
- **唯一允许的修改**（为什么只允许这些：改写会丢失说话时的语气、思维路径、情感状态）：
  - 去掉语音转文字的明显无意义语气词："嗯"、"呃"、"那个那个"
  - 补全省略的主语使句子可读（上下文明确时不补也行）
  - 断句：一段长语音拆成几个逻辑完整的句子
  - 核实错别字：人名、术语、网络用语（如 `WorkBuddy`≠`workbody`、`IMA`≠`Ema`、`setup`≠`塞叉up`、`productive`≠`prodective`）
  - 修正语音转文字不确定的词：当转录明显有误（同音/近音错字、断句歧义）且能根据对多多的了解、背景与说话习惯确定真意时，可直接改正（多多 2026-08-04 明确授权）。例：「射了半天终于是射完了」在"装快捷指令"语境下实为「设了半天终于是设完了」；「测试三每次带门框出去」实为「其实我每次带门框出去」。真意不确定的原字保留，不擅自改。
- **严格禁止**（每一项都会让原话失真）：
  - ❌ 口语变书面语
  - ❌ 压缩句子
  - ❌ 替换用词
  - ❌ 重组语序
  - ❌ 添加用户没说的修饰词
  - ❌ 引号包裹用户原话

## 一、输入（prepare JSON）

由 `voice_to_journal.py --prepare` 产出，每碎片含：

- `frontmatter`：`occasion/focus/topics/highlights/people/knowledge_work/energy/location/related_project/source`（topics/highlights 可能是占位「主题事项 / 有生命力的事」或空 → 反填）
- `body`：苹果转录原话（可含错字，按铁律处理）
- `time`：录音真实时间（本地时区）
- `audio_embed`：`![[Recording 202608040414.wav]]`（**裸文件名**；脚本不移动音频，录音待在原地，Obsidian 按 vault 内文件名内联播放；embed 写的扩展名与实文件不符时脚本已容错修正）
- `audio_status`：ok / missing
- `orphans[]`：有录音无笔记

## 二、输出：当日日记（保留原文）

路径：`07_Journals/01 Daily/<YYYY>/<YYYY-MM-DD>.md`

> ⚠️ **已存在日记 = 追加，绝不覆盖**：若目标 `<生活日>.md` 已存在（例如前一天已手动/自动并过碎片），**先读取现有全文**，本次只追加 prepare JSON 里「时间戳（`### HH:MM`）尚未出现在日记里」的碎片；同步更新 frontmatter 的 `原始记录数量` / `第一条记录时间` / `最后一条记录时间`（取全部碎片 + 孤儿的最小/最大时间）。**已有的所有段落一字不动保留**。整体重写/覆盖既有日记 = 本运行失败。

### Frontmatter（顺序固定，缺失补空；列表项用 `* `）

```yaml
---
type: journal
date: YYYY-MM-DD
weekday: 周X
occasion:
* daily
focus:
* "[[八个人生课题#🌻自我]]"
topics:
* 主题1
highlights:
* 有生命力的瞬间1
people:
* "[[门框]]"
knowledge_work:
* "[[04_KNOWLEDGE WORK/AI学习]]"
energy: high|mid|low
location: 家
related_project:
* "[[个人公司]]"
source: 苹果录音
---
```

- 八课题（名称一字不差，不可改）：🔥个人提升／技能、🌻自我、🍓关系、🌍资源、💫职业、🦋探索、💗美丽、🍀生活方式／健康
- `topics` = 标题 `～` 里偏「主题 / 人事 / 项目」；`highlights` = 偏「情绪 / 生命力」。逐个判断归属，不无脑全塞 topics。
- `[[链接]]` 只放 frontmatter（必须引号包裹，否则 YAML 报错），正文原话一字不动。

### 正文结构（严格顺序）

```
# YYYY.MM.DD｜周X｜日记 ～事项1 ～事项2 ～事项3

日记归属日期：YYYY.MM.DD
创建笔记日期：YYYY.MM.DD HH:MM
原始记录数量：N 条
第一条记录时间：HH:MM
最后一条记录时间：HH:MM

## 🎙️ 当日录音
### HH:MM
![[Recording 202608040414.wav]]
（无转录笔记）   ← 仅孤儿录音加这句

## 今日发生
#### 晨（醒来 — 约 10:00）
#### 上午（约 10:00 — 12:00）
#### 午后（约 12:00 — 17:00）
#### 傍晚（约 17:00 — 19:00）
#### 夜（19:00 以后）
* 用户原句（去语气词、断句、不加引号，不提炼）

## 当时的我
* **原话逐字呈现**：从「今日发生」挑表达情绪/身体/欲望/抗拒/矛盾的原句，逐字放上来；每条后紧跟全角括号 `（）` 写 AI 推断观察到的多多情绪（如：坦然接纳／小骄傲／温柔的期待／由衷的满足）。原话与情绪推断用括号隔开，不混写。
* 非原话的纯总结用 📌 标记；默认优先「原话 +（情绪）」，📌 仅用于无对应原话的归纳。

## 我想到的事情
* 💭 在考虑的可能性
* 📌 触发（<来源>）：<新认知 / 判断>
* ❓ 尚未确定的猜测

## 灵感与创造
* 灵感（原句，保留触发场景）

## 工作与推进
* 工作项（区分计划 vs 已完成）

## 明日与以后
* 明确要做 / 等待别人 / 📌 以后可能考虑

## 今天留下来的几句话 ✨
* 1-5 句最值得留的原话（仅去语气词，不美化）

## 今日小结
📌 80-180 字叙事小结，不鸡汤、不强行积极、不写「成长 / 疗愈 / 成为更好的自己」，带多多口吻。

## AI观察
* 📌 今天最有生命力的瞬间
* 📌 今天最消耗我的事情
* 📌 今天反复出现的主题
* 📌 一个值得留意的线（审慎措辞）
* 📌 一个明天可以留意的问题
```

## 三、各段 SOP（保留原文）

1. **标题**：`YYYY.MM.DD｜周X｜日记 ～事项1 ～事项2 ～事项3`，事项取最开心 / 最有生命力 / 最浓墨重彩的 1-3 个（`～` 后不一定是主题，偏情绪进 highlights、偏主题进 topics）。
2. **元信息**：归属日期 = 生活日；创建 = 本次 10:00 时刻；记录数 = 碎片数 + 孤儿数；首 / 末条时间 = 所有碎片 + 孤儿时间最小 / 最大。
3. **🎙️ 当日录音**：每段 `### HH:MM` + embed；孤儿标「（无转录笔记）」。满足「日记自带音频 + 真实录音时间」。
4. **今日发生**：按时间块（晨 / 上午 / 午后 / 傍晚 / 夜）组织，块内 Bullet 列用户原句（去语气词、断句、核实术语错别字，**不加引号、不提炼**）。多条连续碎片明显讲同一件事 → 合并为一条连贯原话（仅断句，不改写、不替用户补全逻辑）。
5. **当时的我**：从「今日发生」原话里挑表达情绪 / 身体 / 欲望 / 抗拒 / 矛盾的原句，**逐字放上来**，每条后加 `（）` 写 AI 推断观察到的情绪（基于原话措辞 + 对多多的了解，不臆造、不心理诊断）。例：`- 今天我认为是一个非常 mindful 的一天，不是很 productive（坦然、对自己"不 productive"没有焦虑，反而有点满意）`。📌 仅用于确实无法对应原话的纯总结。
   **我想到的事情 / 灵感与创造 / 工作与推进 / 明日与以后**：从原话提取，原句呈现。
   - 我想到的事情每条标 💭 / 📌 / ❓；📌 项必须交代触发源（"触发：今天… → 我…"），不要只留结论。
   - 工作与推进：区分计划 vs 已完成（"我要去做XX" 记成"要去做XX"，不记成"做了XX"）。
6. **今天留下来的几句话 ✨**：挑原话，只做必要口语清理，不改写成更"优美"的句子。
7. **今日小结**：📌 80-180 字，不鸡汤、不强行积极，写出这一天真正的主题 / 张力 / 变化，接近用户语言风格。
8. **AI观察**：📌 审慎，用"可能 / 看起来 / 值得继续观察 / 仅根据今天的记录还不能确定"，严禁心理诊断或确定性人格判断。

## 四、字段反填规则

- `topics` / `highlights` 占位 / 空 → 从正文反推真值，推不出留空，**绝不编造**。
- 跨碎片 frontmatter 取并集去重；occasion 取并集；topics / highlights 各自合并去重。
- 一天无碎片 → 不写空日记。

## 五、日界线与整理范围

- 日界线 **06:00**（生活日从早起开始，凌晨几点还属"昨天"）。脚本 `--prepare / --archive` **不传 `--date`** 时自动算上一个生活日（当前 ≥ 06:00 → 昨天；< 06:00 → 前天），收集「生活日当天 + 次日 06:00 前」的笔记 / 音频。
- 10:00 自动化**不传 --date**，由脚本自动判定，正确收纳「昨晚录制、文件名带昨天」的笔记（早期版传 `--date 今天` 会漏掉这些）。

## 六、10:00 自动化用法

1. `.../voice_to_journal.py --prepare`（不传 --date，自动算上一个生活日）：校验 embed 对上真实音频、就地修正扩展名（embed 写 .m4a 实 .wav 时自动容错）、输出 JSON。**不移动、不删除任何音频**（录音由快捷指令落在 vault 内 inbox/voice，笔记已自带 embed）。
2. **本 skill（LLM 执行）**：读 JSON，按第三节**保留原文**产出 `<生活日>.md`。
3. `.../voice_to_journal.py --archive`（不传 --date）：碎片移 `done/`。

## 七、已知约束

- 碎片 frontmatter 可能全角冒号（`source：苹果录音`）和 `•` 符号，解析兼容（脚本已处理）。
- 苹果转录错字：术语 / 拼写（WorkBuddy / IMA / setup / productive）可修正；**同音 / 近音错字、断句歧义，若根据对多多的了解 / 背景 / 说话习惯能确定真意，可直接改正（多多 2026-08-04 授权）；真意不确定时保留原字**。例：「射了半天」在装快捷指令语境下 = 「设了半天」；「测试三」=「其实我」。
- 录音格式：m4a / wav / mp3（快捷指令现常产 .wav）。embed 写的扩展名与实文件不符时脚本已容错，日记直接用裸文件名 `![[Recording 202608040414.wav]]` 内联播放；**脚本绝不移动/删除音频**，录音始终待在 vault 内 inbox/voice。
- 真版在 `references/daily-diary-skill-full.md`，改本 skill 前先读真版对齐。
