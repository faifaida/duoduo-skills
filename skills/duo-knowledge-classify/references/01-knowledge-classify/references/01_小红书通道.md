## A1. 架构（关键认知）

小红书四层反爬：**签名层**(x-s/x-t)、**传输层**(TLS JA3)、**设备层**(Canvas/WebGL)、**行为层**(节奏)。纯 requests 秒封。

混合架构：
1. **按 board 枚举 noteId** — osascript 驱动本机真实 Chrome 打开 `board/<id>/` 滚动提取 `noteId + xsec_token`。稳定、不易触发风控。
2. **签名 API 抓详情** — Spider_XHS 的 `get_note_info`（POST `/api/sns/web/v1/feed`，Node execjs 跑 crypto-js/jsdom 出 x-s/x-t）。
3. **落盘** — `process.py` 的 `note_md()`，三段式 + frontmatter。

> 为什么不用 Spider_XHS 的 `get_user_all_collect_note_info`？它只返回「全部收藏」混一起，**没有 board 级接口**，会丢 8 个专辑的归类。所以必须保留 Chrome 枚举。

## A8. 已知限制

- **账号级限流**：页面回 "Too many requests" → 换工具也没用，等限流解除（常 >24h）。
- **服务端隐藏笔记**：原作者私密/注销的，任何网页方式都拿不到。属已知限制，**不是漏抓，别反复重试**。
- **Chrome 依赖**：Mac 休眠 / Chrome 未登录 / 模态弹窗（`-600`）会失败，重启 Chrome 重跑，已抓的不丢。
- **签名时效**：小红书每月轮换签名算法，需跟进上游 `cv-cat/Spider_XHS`。

## A9. frontmatter 铁律

**属性值禁止 `[[ ]]`** —— YAML 会把 `[[ ]]` 当嵌套列表，整块 frontmatter 解析失败、Obsidian 全部属性不显示。`focus` 用纯文本列表 `focus: ["🌻自我", "🔥个人提升／技能"]`，wikilink 只放正文。
（`knowledge_work` 字段例外：指向 T10 的 wikilink 需写成引号包裹的字符串。）

## A12. 无标题 URL 批量补抓真实标题（WebFetch 法，2026-08-07 实战验证）

**场景**：知识地图里大量 `[[(无标题) - 2026-07-21_NN]]` 行，源文件（`00_SOURCES/小红书/<专辑>/`）只有 URL、无标题。需要把真实笔记标题补回地图的 wikilink。

**为什么用 WebFetch 而非签名 API**：本机住宅 IP 对小红书 detail 接口有限流/风控，且源文件 body 只是 URL（无签名所需参数）。WebFetch 走 server 出口，绕开本地限流；实测单批 10 条、连续多批全部成功返回，**0 失败**（文档里写的"155/52 条失败"是错的悲观假设，以实测为准）。

**工作流（幂等、可断点续跑）**：
1. **从地图本身重生成待抓清单**（不要依赖 `/tmp`，会话中会丢）：扫描含 `(无标题)` 的行 → 提取 URL → 排除已抓过的 → 写 `remaining_urls.txt`。
2. **WebFetch 每批 10 条**，prompt 固定：`Return ONLY the note's title text. If you cannot access it (login required / blocked), reply exactly BLOCKED.`
3. 追加到 `relfix_map.tsv`（`url \t title \t`，full title 保留 fidelity，地图显示时截断 ≤60 字）。
4. **幂等回写脚本 `apply_now.py`**：按 URL 匹配行 → 改写 wikilink 为 `[[标题 - 小红书]]` 并清空 `(提取失败，待补)` 占位；可重复跑、不重复改。
5. **验证**：`grep -c "提取失败"` 应为 0；`grep -c "(无标题)"` 仅剩「别名已带真实标题、stem 仍 `(无标题)_NN`」的历史行（显示正常，可接受，因源文件命名即 `(无标题)_NN`）。

**坑（已踩）**：
- `/tmp` 会被清 → 进度直接写回地图 + tsv 累积，不依赖 `/tmp` 持久化。
- WebFetch 偶尔返回「相关笔记 feed」而非单篇 → 取顶部 `**标题**:` 行当真实标题。
- 标题本身是长列表（如"聊出感情的18个话题"）→ tsv 存全文，地图显示截断。
- 合并地图时两套源表列结构可能不一致（部分行 URL 列空、部分带 `url:`）→ 跨地图去重应**以显示标题为键**，不以 URL 为键。

**适用**：任何 T10 地图的"无标题 URL 补真实标题"批量任务；与 A4 失败页重抓（签名 API）互补——WebFetch 管"有 URL 但没标题"，A4 管"签名 API 没抓到的失败页"。
